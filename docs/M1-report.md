## สิ่งที่ต้องรู้ / ความเสี่ยง

1. **repo ยังเป็น Public** ผมจึงไม่ได้ commit `SPEC.md`, `CODEX_PROMPT.md` และ `/reference` (มีเบอร์โทรช่าง ยอดเงิน และสมุดบัญชี) เปลี่ยน repo เป็น Private แล้วลบบรรทัด `/reference/` ใน `.gitignore` จากนั้น commit ได้เลย เทสต์ที่ต้องใช้ไฟล์ reference จะข้ามไปเองถ้าไม่มีไฟล์
2. **ล็อก PIN มีช่องโหว่ทางทฤษฎี**: การล็อก 5 ครั้งบังคับผ่าน edge function `login` แต่ Supabase ยังเปิดให้ล็อกอินตรงด้วย anon key ได้ (ซึ่งมี rate limit ของ Supabase เองคุมอยู่) PIN 6 หลักมี 1 ล้านแบบ ถือว่ารับได้สำหรับทีมภายใน ถ้าต้องการปิดสนิท ต้องเปลี่ยนไปใช้ custom JWT (ทำได้ใน M2)
3. ไฟล์ทดสอบมีแถวยอดค้างของห้อง **"B5-H (ออฟฟิตเก่า)" 8,976 บาท ซึ่งไม่ตรงกับชื่อห้อง "B5-H"** ยอดรวม 41,080 ในสเปกจึงไม่ได้รวมแถวนี้ ระบบจะขึ้นเตือนในรายงานตรวจพร้อมแนะนำชื่อห้องที่น่าจะใช่ — **ถ้าในไฟล์จริงเป็นแบบเดียวกัน ต้องแก้ชื่อห้องก่อนนำเข้า ไม่อย่างนั้นยอดค้างนี้จะหาย**
4. แบบฟอร์มจริงรอบ ต.ค. ยังไม่มีเลขมิเตอร์ครั้งนี้และเลขบัญชีรับโอน ระบบจะไม่ให้วางบิลจนกว่าจะจดครบ ส่วนเลขบัญชีให้กวางกรอกในแท็บตั้งค่าหรือในแบบฟอร์ม

## คำตอบจากคุณอาร์ต (1 ต.ค. 69) — แก้ในระบบแล้ว

1. **สร้างบัญชี**: เป้อและนุ้ยในฐานะผู้จัดการพิษณุโลก สร้าง/แก้/ปิดบัญชีได้ทุกระดับเหมือน CEO · กวางทำได้ทุกระดับยกเว้น CEO · แท็บ "ผู้ใช้งาน" มีให้อาร์ต เป้อ นุ้ย กวาง · ทุกคนยังเปลี่ยนสิทธิ์หรือปิดบัญชีของตัวเองไม่ได้
2. ห้องว่างที่ยังมียอดค้าง = บิลค้างรับ ✓ (ตามเดิม)
3. ห้องพนักงานยังไม่จดไฟ = เตือนแต่ไม่ห้ามวางบิล ✓ (ตามเดิม)
4. **เงินสำรองนุ้ย**: กวางกรอกยอดยกมา และแก้ได้ถ้าผิด โดยต้องใส่เหตุผล ระบบบันทึกเป็นรายการปรับส่วนต่าง ไม่ลบของเดิม จึงยังย้อนดูได้ว่าแก้จากเท่าไรเป็นเท่าไร

ยังเปิดอยู่: ค่าปรับเพดานรวม 3,100 ต่อบิล · ห้องที่เปลี่ยนเป็น "ว่าง" ยังไม่ปิดผู้เช่าเดิมอัตโนมัติ · ช่างเบอร์ซ้ำจับคู่ด้วยชื่อ
